## 上线前还需要决定

这些不是代码缺失，而是需要产品所有者提供或确认的外部条件：

1. 选择部署平台与域名，并设置真实 `NEXT_PUBLIC_BASE_URL`。
2. 在平台的加密环境变量中设置 `DEEPSEEK_API_KEY`，按需设置 Gemini 和社区数据源凭证。
3. 确认是否开启 `WORK_LORE_STREAMING`；平台必须支持不缓冲 SSE。
4. 确认冷知识内容库的发布审核流程。
5. 若进入多实例或公开高流量阶段，把内存限流迁移到 Redis/Upstash 一类共享存储。
6. 若允许运营人员在线增删冷知识，把 JSON 内容库迁移到数据库或 CMS。

- 社区评论、用户投稿、点赞与公开个人主页。
- 管理后台、内容审核队列、来源失效巡检与运营数据看板。
- 多语言界面和英文/日文内容库。
- 更完整的芽衣表情包、Live2D/语音、情绪反馈和更多互动彩蛋。
- 真正的离线收藏包；当前仅缓存静态资源、离线页和访问过的页面。
- 多模型路由、费用预算、任务队列和分布式可观测性。

## 安全审计说明

可以自动修复的 `form-data`、`protobufjs`、`ws` 与旧 Vitest 问题已经修复，critical 为 0。

`npm audit` 仍会报告 3 个 high，来源是 Next.js 官方包固定依赖的 PostCSS 8.4.31 与 Sharp 0.34.x。当前官方 Next 16.2.11 也固定使用相同版本，因此没有不改变框架内部依赖约束的安全升级路径。不要执行会把 Next 降级到 9.3.3 的 `npm audit fix --force`。详见仓库根目录 `SECURITY.md`。

## 回退方法

阶段提交可以用 `git log --oneline` 查看。推荐在新分支上执行：

```powershell
git revert <commit>
```

不要使用 `git reset --hard` 覆盖历史。关键阶段包括：

- `da7386f`：改造前基线
- `9586ee1`：双主题响应式体验
- `765e580`：芽衣品牌状态
- `6a63325`：工程门禁与安全基线
- `7de5c87`：可安装离线 PWA
- `4295c7f`：Next 15 LTS
- `ca2739b`：浏览器验收 UI 修复
